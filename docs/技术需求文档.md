# MistakeCoach 技术需求文档

> 版本 v1.15 · 里程碑驱动，不设固定时间线；按 M1→M4 阶段顺序推进
> 一句话定位：面向初高中学生的 H5 应用——拍下做错的题（连同错误作答），AI 先引导还原思路、定位错因，再讲解；对话结束自动生成结构化错题卡，可导出长图分享、沉淀进错题本。

---

## 1. 产品概述

### 1.1 目标用户
- 初高中学生（自用），家长可协助打印/复习错题卡
- 核心场景：作业/试卷发下来后，对着错题拍一张 → 和 AI 聊明白 → 沉淀错题卡

### 1.2 差异化价值（简历/面试叙事核心）
| 竞品 | 做法 | MistakeCoach 的差异 |
|---|---|---|
| 作业帮 / 小猿搜题 | 拍题 → 直接给答案 | 学生抄完即忘，无错因沉淀 |
| MistakeCoach | 拍错题（含错误作答）→ 苏格拉底式对话还原思路 → 定位错因 → 生成错题卡 | 教"为什么错"而不只是"怎么对"；对话即数据，笔记自动生成 |

三个核心设计（面试重点）：
1. **多模型分工**：视觉模型只做识别（一次调用），文本大模型做对话与笔记生成，成本极低且各取所长
2. **错因靠对话"钓"**：引导模式开场先问"你当时怎么想的"，学生思路全程记入上下文档案，笔记从对话提取而非臆测
3. **固定 JSON Schema**：错题卡由 AI 按固定 Schema 输出，前端按 Schema 稳定渲染长图

### 1.3 明确不做（写进简历"后续规划"）
- 用户账号体系 / 手机号登录
- 艾宾浩斯复习提醒、学情统计报表
- 错题批量导入、手写 OCR 深度优化

---

## 2. 用户主流程

```
拍题页 → 选图/拍照 → 上传识别 → 核验页（人工二次核验，详见 3.1）
       → 对话页（默认引导模式，可一键切换讲解模式，SSE 流式）
       → 点「我懂了，生成笔记」→ 生成错题卡
       → 错题卡页（预览 + 保存长图 + 存入错题本）
       → 错题本（牌堆浏览 + 维度切换，入口=拍题页顶栏图标；桌面端表格管理视图）
```

### 3.1 识别核验页（FR-3 详设）

手写体、反光、歪斜都会带来识别误差，因此在 GLM-4V-Flash 之后设计人工二次核验环节，形成"AI 识别 + 人工兜底"闭环（human-in-the-loop）：

- **对照展示**：原图（可缩放查看）与识别结果对照排布
- **可编辑字段**：学科 / 年级段（行内胶囊单选，无弹层遮罩）、题目原文（textarea，公式简记学生可直接改写）、我的错误作答（textarea）
- **公式预览**：题干编辑区下方实时预览（兼容 $...$ LaTeX，简记原文直接展示），边改边看
- **智能提醒**：
  - `has_handwriting=false` 时提示："没识别到你的作答，建议补充当时的错误思路，错因分析会更准"
  - 题干为空或过短（<10 字）禁止进入对话
- **两个出口**：`确认无误，开始对话`（携带核验后文本进入对话页）；`重新拍一张`（返回拍题页）
- 核验页为纯前端步骤，不新增 API；对话与笔记接口的输入一律以核验后文本为准

### 3.2 错题卡视觉规范（风格 B · 手账荧光）

皮肤 token（已通过可视化稿确认）：
- 底色 `#FFFBEB`（米黄纸感）· 正文 `#44403C` · 边框 `#E7D8A8` · 次要文字 `#A16207`
- 强调色 `#D97706` · 荧光划重点 `#FEF08A` · 错答红笔 `#DC2626`（虚线下划）· 胶带元素 `rgba(250,204,21,0.45)`
- 圆角 16px · 错答标签/知识点用黄胶囊（`#FDE68A` 底 `#92400E` 字）

信息顺序（从上到下，与 Schema 一一对应）：
1. 学科·知识点标签 + 日期
2. 题目（考点关键词荧光划重点）
3. 我的错答（红笔虚线样式）
4. 错因胶囊 + 一句话分析
5. 正确解法（分步，编号）
6. 顿悟原话（左侧强调色竖条引用样式）
7. 变式练习（默认折叠，点「做完对答案」展开）
8. 品牌水印「MistakeCoach · 让每道错题都有交代」

触感规范：
- 按下 `scale(0.955)` / 90ms ease-out；松手回弹 320ms `cubic-bezier(0.34, 1.8, 0.64, 1)`（弹性过冲）
- 键盘可达（Tab 聚焦 + 空格触发）；`prefers-reduced-motion` 时禁用动效

防抖规则（消灭布局跳动）：
- 原图按固定宽高比占位，加载前不塌陷
- KaTeX 公式渲染完成前显示骨架占位，渲染后不再变高
- 长图导出前等待全部渲染完成（公式/字体 ready 后再 html2canvas）

### 3.3 错题本牌堆交互（FR-13 详设）

- **形态**：错题本页以牌堆呈现（P1 桌面端仍用表格视图）；点击牌堆，整串牌**向右推开**（牌不旋转、仅水平平移，如手指按住一叠牌抹开），顶牌先动、逐张错开约 22ms；再点击空白处收拢
- **查看**：推开后**点击某张牌 → 完全抽出**（居中放大浮层展示详细内容：题目公式渲染、答案，可一键进入完整错题卡页），点空白或「放回牌堆」收回；**悬停半抽（上移 16px 预览）仅在牌堆已推开后生效且仅桌面端渐进增强**——收拢态无悬停效果，触屏直接点击
- **动效**：推开/收拢/整抽 300ms 弹性曲线 `cubic-bezier(0.34, 1.8, 0.64, 1)`；悬停与摘要淡入 120ms；推开间距按牌数自适应，保持整串在屏宽内
- **牌堆上限**：单堆最多 12 张，超出折叠为"更多"堆（防止推开过宽）
- **分组维度**：默认按**学科**分堆，顶栏提供维度切换（学科 / 错因类型 / 知识点）；知识点维度天然碎片化（常为单张成堆），仅作筛选辅助而非默认分堆

**错题卡字段（固定 JSON Schema，前端渲染与 AI 输出共同契约）：**

```json
{
  "id": "uuid",
  "created_at": "2026-11-14T10:00:00Z",
  "subject": "数学",
  "grade_band": "初中",
  "knowledge_points": ["一元二次方程"],
  "question": "题目原文，公式为 LaTeX",
  "student_wrong_answer": "学生当时的作答/思路",
  "wrong_reason": {
    "category": "概念不清 | 计算失误 | 审题偏差 | 方法缺失",
    "analysis": "基于对话证据的错因分析（1-3 句）"
  },
  "correct_solution": ["步骤1（LaTeX）", "步骤2"],
  "final_answer": "最终答案",
  "variant_question": "1 道同考点变式练习",
  "variant_answer": "变式题答案与简析（前端折叠展示）",
  "insight_quote": "对话中学生顿悟的原话（无则空字符串）",
  "chat_summary": "对话要点回顾（2-3 句）"
}
```

### 3.4 路由设计（vue-router）

六个路由页面，主流程线性（拍→核→聊→卡），浏览器返回键自然回退：

| path | 页面标题 | 内容 | 守卫（直访/刷新） |
|---|---|---|---|
| `/` | 拍题 | 拍照/相册（手机）、拖拽/点选/粘贴（桌面）、识别 loading | 默认首页，无守卫 |
| `/verify` | 确认题目 | 原图对照、字段编辑、LaTeX 预览 | 识别数据仅在内存，刷新/直访 → 重定向 `/` |
| `/chat` | 错题对话 | 气泡流、双模式切换、生成笔记按钮 | 有草稿 → 恢复续聊；无核验文本且无草稿 → 回 `/` |
| `/card/:id` | 错题卡 | 卡片渲染、导出长图、存入错题本 | localStorage 查无 id → 回 `/book` |
| `/book` | 错题本 | 牌堆/表格视图、维度切换、未完成对话入口 | 常驻入口，无守卫 |
| `/settings` | 设置 | 访客自带 Key 配置（BYOK，3.6） | 常驻入口，无守卫 |

已定决策：
- 核验页独立路由（保证返回键行为正确）；`/card/:id` 一页两用（新生成的卡与错题本点开的卡同路由）
- 错题本、设置入口 = 拍题页顶栏图标（错题本 + 设置，界面干净）
- 页面标题中文，逐页同步 `document.title`
- 页面切换动效：主流程右滑进入约 120ms、返回左滑；`prefers-reduced-motion` 时禁用
- `/chat` 刷新靠 localStorage 草稿恢复（FR-12）；`/verify` 刷新即回拍题页（刻意取舍，不加后端会话）

### 3.5 移动端 / 桌面端适配（全页自适应）

定性：手机优先 H5 网页（非 App、免安装），响应式 web 电脑完整可用——demo 链接大概率被面试官在电脑上打开。断点 768px，组件复用，差异集中在布局容器与图片入口：

| 页面 | 手机端（<768px） | 桌面端（≥768px） |
|---|---|---|
| `/` 拍题 | 「拍照」「相册」大按钮（capture 调相机） | 大拖拽区：拖入 / 点选 / Ctrl+V 粘贴三通道，下方三步流程说明 |
| `/verify` 核验 | 原图在上、编辑字段在下 | 左右对照：左原图大图，右编辑表单 + KaTeX 实时预览 |
| `/chat` 对话 | 全屏气泡流，题目信息折叠在顶栏 | 左栏固定「题目+我的错答」参考卡，对话流限宽 760px |
| `/card` 错题卡 | 卡片全宽，底部操作栏 | 卡片居中（保持竖版长图比例），操作按钮横排 |
| `/book` 错题本 | 牌堆交互（3.3） | 默认表格管理视图，可切牌堆视图（hover 半抽） |
| `/settings` 设置 | 表单卡片全宽 | 居中表单卡片 |

- 桌面图片三通道实现：`dragover/drop` + 点击 `<input file>` + `paste` 事件（`clipboardData`），纯前端约 50 行，预览逻辑与手机端复用；**不做"示例题"预置按钮**
- 桌面 hover 交互（牌堆半抽、按钮态）为渐进增强，移动端靠点击完成全部操作

### 3.6 设置页（FR-14 详设）

本服务**不内置任何模型 Key**（纯 BYOK）——识别与对话全部使用访客自己的 Key，公网 demo 不存在开发者额度被滥用的可能：

- **入口**：拍题页顶栏齿轮图标；路由 `/settings`，无守卫（常驻可访）
- **识别**：固定智谱 GLM-4V-Flash（免费），需填智谱 Key；未填 Key 时拍题页显示引导横幅
- **对话/笔记模型可选（胶囊单选）**：DeepSeek（便宜）/ 智谱 GLM-4.7-Flash（免费，高峰期可能限流 429，错误信息会提示切换）；选智谱时与识别共用同一把 Key
- **存储**：localStorage 键 `mc_keys`（zhipu / deepseek / chatProvider），请求时随 `X-Zhipu-Key` / `X-Deepseek-Key` 头发送，后端即用即弃，不落库、不写日志
- **无 Key 时**：后端返回 400 + 明确提示去设置页；服务端**不再读取** .env 中的任何模型 Key
- **服务端可配项**：仅模型名覆盖（`ZHIPU_MODEL` / `DEEPSEEK_MODEL` / `ZHIPU_CHAT_MODEL`），部署无需配置 Key 环境变量

## 4. 非功能需求

- **性能**：识别接口 P95 < 8s；对话首 token < 3s；长图导出 < 3s
- **兼容**：iOS Safari / Android Chrome / 微信内置浏览器；桌面 Chrome / Edge（自适应布局，断点 768px）

## 6. API 设计

> 通用约定（纯 BYOK）：服务端不内置任何模型 Key，所有模型调用的 Key 均来自访客请求头（`X-Zhipu-Key` / `X-Deepseek-Key`，见 3.6）；`chat` / `note` 请求体携带 `chat_provider`（deepseek | zhipu）选择对话供应商；缺 Key 返回 400 + 设置页引导文案。

### 6.1 POST /api/recognize
- 入参：`multipart/form-data { image }`
- 处理：转调 GLM-4V-Flash（图片 base64），解析 JSON（模型输出的 LaTeX 反斜杠非法转义由后端统一容错修复）
- 出参：`{ "subject", "question_text", "student_work", "has_handwriting" }`
- 失败：模型返回非 JSON 时后端重试一次，仍失败返回 502 + 提示文案

### 6.2 POST /api/chat （SSE）
- 入参：`{ "question_text", "student_work", "state": { "phase", "hint_level", "mode" }, "messages": [{role, content}] }`（`state` 由前端状态机维护，后端拼为末尾状态指令，保持前缀缓存稳定）
- 入参说明：`question_text` / `student_work` 以核验页人工确认后的文本为准，识别结果不直接进对话
- 无状态设计：前端每次携带完整对话历史，后端不存会话（MVP 最简）
- 处理：注入固定基底 system prompt（含双模式与全部阶段规则），将 `state` 拼为末尾状态指令，转调 DeepSeek
- 出参：SSE 事件流 `data: {"delta": "..."}`；流末尾先发 `data: {"state": {...}}`（后端解析回复末尾标记得到的新状态）再发 `data: [DONE]`
- 状态切换：前端硬规则（关键词命中、卡壳计数）+ 模型末尾标记共同驱动；详见 7.5

### 6.3 POST /api/note
- 入参：`{ "question_text", "student_work", "transcript": [...] }`
- 处理：DeepSeek 按 3. FR-7 的 Schema 生成错题卡，强制 JSON 输出
- 出参：错题卡 JSON（Schema 见 FR-7）
- 容错：Schema 校验失败重试一次；`category` 枚举外的值归为"方法缺失"

## 7. Prompt 设计要点（存 `backend/prompts/`）

**识别（GLM-4V-Flash）**
```
你是试卷识别助手。图片是学生做错的题目照片，图中可能同时出现多道题。
任务：只识别学生做错的那一道题——通常是手写作答、演算或红笔批改痕迹最集中的那道；无法判断时选手写痕迹最多的一道。
输出 JSON：{ "subject": "数学/物理/化学/语文/英语/其他",
  "question_text": "该题完整题干（保留题号与出处，如 '6. (2014·河南省郑州一中检测)'），选择题需一并给出 A/B/C/D 各选项。数学表达式用学生能看懂能改写的简记：根号写 √，平方写 x²，分数写 a/b，不要用 LaTeX 代码（$...$、\\frac 等一律不要）",
  "student_work": "整理学生手写作答，不是逐字照抄，不要抄印刷体选项：第一句写学生自己写的选项，如'选 A'；注意区分——学生写下的选项是他的作答，老师红笔批改的另一个选项是正确答案，不要混淆（写成'选 A（卷面批改为 B）'）。有演算再摘录 1-2 行关键步骤（用同样简记），学生手写的小疑问也可注明；没有手写内容则空字符串",
  "has_handwriting": true/false }
只输出 JSON。不要解题，不要评改。不要输出图中其他题目。
```

**引导模式（DeepSeek system）**
```
你是初高中错题教练。已知题目：{question_text}；学生当时的作答：{student_work}
规则：
1. 目标是让学生自己发现问题，除非学生要求，不给完整答案。
2. 第一轮先请学生讲讲当时的思路（解释他为什么这么做）。
3. 每轮只问一个问题或给一个提示，口语化、鼓励式。
4. 内部持续判断错因类型：概念不清/计算失误/审题偏差/方法缺失。
5. 学生说"直接讲/给我答案/不会了"→ 切入讲解：从错因讲起，给分步解析。
6. 数学公式一律 LaTeX。不要输出内部记录。
7. 计算自检：算出的答案与学生作答/卷面批改矛盾时，先重算自己；确有把握再温和指出卷面批改可能有误，带学生一起验算，不盲从卷面（面试亮点：AI 不盲从权威答案）。
```

**讲解模式**：同上身份，直接给"错因 → 分步解析 → 最终答案 → 1 句防错提醒"。

**笔记生成**：输入对话 transcript，按错题卡 Schema 输出 JSON；题干/作答里的简记公式在写入卡片时统一转成 LaTeX；错因分析必须引用对话中的学生原话作为证据；提取学生顿悟原话填入 `insight_quote`；变式题同考点、难度相当，并输出 `variant_answer` 供前端折叠展示；最终答案先重算自检再输出。

## 7.5 对话引擎详设（硬状态机 + 缓存友好）

四阶段状态机：P1 还原思路（1-2 轮）→ P2 定位错因（1-2 轮）→ P3 引导修正（提示梯度 L1 方向提示 → L2 关键点提示 → L3 步骤骨架 → L4 完整讲解）→ P4 确认理解（复述/口算变式）。关键工程决策：

- **固定基底 system prompt**：全部阶段规则与双模式规则写在同一个 system prompt，不随阶段切换
- **状态走末尾消息**：每轮请求在消息末尾追加一条状态指令（当前 `phase` / `hint_level` / `mode`），由前端状态机计算
- **为什么这样设计（缓存）**：LLM 前缀缓存按请求前缀匹配，若把阶段写进 system prompt，每次阶段切换都会使整个对话前缀失效，缓存全丢；状态放末尾则前缀稳定，除新增一轮外全部命中（DeepSeek 缓存命中部分输入费用约为未命中的 1/10）
- **阶段推进判定**：模型每轮回复末尾输出机器可读标记（如 `⟦PHASE:P3|HINT:L2⟧`），前端解析驱动状态机，渲染前剥离标记
- **硬规则兜底**：连续 2 轮「不知道/不会」→ `hint_level` +1；关键词「直接讲/给我答案」→ `mode=direct`（等价 L4）
- **模式切换 UI（已定稿）**：对话页顶栏放「引导｜讲解」分段器（方案 A，常驻显眼，当前模式一目了然）；手动切换与关键词自动切换行为一致，AI 下一条消息立即按新模式回答；手动切换后 AI 立即按新模式主动回复一条（不等学生再发言）；前端 SSE 有 45s 无响应超时兜底（超时/中断给出可读报错，不再空气泡卡死）
- **模式认知三触点（已定稿）**：让学生秒懂两模式区别，不靠说明文字靠行为示范——
  1. 首次进入对话页插一条高亮说明气泡：「引导模式：我不会直接给答案，会一步步问你，带你找到错在哪。想直接听懂？点顶栏『讲解』。」；localStorage 记录已看，此后不再出现
  2. 切换气泡带行为说明：切到讲解 →「已切换到讲解模式 —— 我会把错因和步骤直接讲给你听」；切回引导 →「已切换回引导模式 —— 我会继续问你，带你自己想通」
  3. P1 开场白本身就是引导模式的行为示范（AI 提问而非甩答案），无需额外解释
- **P1 开场**：AI 主动引用照片中的错答——"我看到你写了 X，能说说当时是怎么想的吗？"
- **收口**：P4 达成后 AI 在消息流中插入建议气泡「要不要生成错题卡？」；对话草稿实时存 localStorage 支持续聊

## 8. 阶段划分（里程碑驱动，不设时间点）

按 M1→M4 顺序推进，每个阶段有明确完成标准（DoD），完成即进入下一阶段：

| 阶段 | 内容 | 完成标准（DoD） |
|---|---|---|
| M1 识别链路 | 后端骨架 + `/api/recognize` 联通；前端脚手架 + 拍题页 + 核验页 + 设置页 | 手机传图返回正确 JSON，核验页可修正后进入对话；设置页 Key 保存/清除生效 |
| M2 对话引擎 | `/api/chat` SSE + 硬状态机（阶段/提示/模式）+ 对话页（气泡/KaTeX/切换按钮） | 完整走通 P1→P4 引导对话，卡壳升级与切讲解均生效 |
| M3 错题卡闭环 | `/api/note` + 错题卡页 + 长图导出 + 错题本筛选 + 草稿续聊 | 一条龙：拍→核→聊→卡→存→续聊 |
| M4 交付打磨 | 桌面端管理视图 + 部署上线 + README + 简历话术 | 公网可访问 demo；README 含架构图与亮点说明 |

范围原则：M1-M3 是核心闭环，M4 可按进度取舍（部署可降级为本地演示）。

## 9. 风险与应对

| 风险 | 应对 |
|---|---|
| 手写错答识别不准 | 核验页人工二次核验兜底（原图对照 + 全字段可编辑 + LaTeX 预览）；识别 prompt 强调区分印刷/手写 |
| DeepSeek 输出 JSON 偶发不合法 | `response_format=json_object` + 失败重试一次 + 前端容错提示 |
| html2canvas 在 iOS 字体/公式渲染异常 | 卡片用系统字体 + KaTeX 完成后再截图；M3 阶段真机验证 |
| SSE 被代理缓冲 | 部署时关闭 nginx 缓冲或改用 fetch ReadableStream |
| 进度风险 | M1-M3 核心闭环优先，M4 可后置或降级（桌面端用响应式、演示走本地 + 内网穿透） |
| 一张照片多道题 | 识别 prompt 选最清楚的一道，并告知"检测到多道题，本次先处理第 1 道" |
| 拍的不是题目 | 识别返回 `has_question=false`，提示重新拍摄 |
| AI 解答出错 | 笔记生成时对最终答案重算自检一遍；独立验证器记为已知限制 |
| 学生跑题/刷屏 | 对话 prompt 要求温和拉回错题 |
| SSE 断线 | 前端显示"重试"，重发最后一条消息 |
| 照片含个人信息 | 识别 prompt 明确忽略姓名/人脸等个人信息不输出 |
